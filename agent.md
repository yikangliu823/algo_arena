# Agent rules for this repository

## Code style: no AI slop

These rules apply to every change and override default verbosity. If a rule conflicts with an explicit user
instruction, the user wins; otherwise they are non-negotiable.

### Comments
- Never state the obvious. If the code already says it, delete the comment.
- No comment on every line. At most one short comment per logical block, only where the reason is non-obvious.
- Comments explain why, never what.
- No emojis in code or comments. No "Generated by AI", "NOTE:", or "IMPORTANT:" banners.
- No commented-out code. Delete it; version control remembers.
- Docstrings only on public functions and classes, one or two lines, and only if they add information beyond the
  signature. Never restate the function name as a sentence.

### Structure
- No premature abstraction. One use case gets one straightforward implementation. No Factory, Strategy, or Builder
  patterns unless there are at least three real variants.
- No Manager, Helper, Util, Common, or Misc god-modules. Put logic where it is used.
- Flat is better than nested. Two levels of nesting maximum; extract a function instead of adding a third.
- No dead code, unused imports, unused parameters, or placeholder stubs. If it is not called, delete it.

### Defensive coding
- Handle only errors the caller can act on. Do not wrap everything in try/except.
- Never silently swallow exceptions. Never `except Exception: pass`.
- No redundant guards: no None-checks three functions deep, no re-validating already-validated input.

### Naming
- Concrete names: `retry_delay_s`, not `data`, `info`, `temp`, or `foo`.
- No marketing adjectives in identifiers: no `enhanced_`, `advanced_`, `smart_`, `robust_`, or `seamless_` prefixes.

### Output text
- Error messages and logs are plain sentences. No emojis, no exclamation stacks.
- No sycophantic phrasing anywhere in code, comments, or messages.

### Tests
- Every test asserts observable behavior. No tests that only verify a mock was called.
- One behavior per test, named after the behavior.

## Standing user instructions that take precedence

- Every code file starts with the author header (Author, Version, Created, License, Copyright; see LICENSE.md).
- Public JavaScript functions keep JSDoc type tags (`@param {Type}`, `@return {Type}`, `@throws`): Google JS style
  7.8 requires types, and `tsc` (verify/tsconfig.json, checkJs) reads them. Descriptions after a tag are dropped when
  obvious. This replaces round 2's "Google-style docstring on every function" (user decision, round 3).
- site/index.html is generated; its comments live in tools/index-comments/*.json and follow the rules above.
